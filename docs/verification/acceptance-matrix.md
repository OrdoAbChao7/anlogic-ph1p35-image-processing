# 方案与计划验收表

验收条件建立：2026-10-03；入口整理：2026-10-20。本轮保留G1–G8测试方法和通过条件，不降低数值或覆盖要求。本表只定义验收，实际状态见STATUS。

## 执行入口与证据层级

先读 [STATUS](../project/STATUS.md) 定位当前版本，再用 [PHASES](../project/PHASES.md) 判断前置依赖、[Agent工作流](../development/agent-workflow.md) 选择本轮任务、[工具链](../development/toolchain.md) 调用实际入口。原图基线、工业修复候选和独立模块报告不能混用。

- SIM_PASS：具体输入和覆盖范围的模型/RTL通过。
- BUILD_PASS候选：该次构建/最终时序通过；关键告警、约束覆盖、视觉与硬件仍须分别核对。
- USER_REPORTED_ON_BOARD：用户报告的现象；尚未形成完整版本绑定与测试证据。
- VERIFIED_ON_BOARD：具体功能在绑定版本和条件下实测通过；不自动代表所有G阶段通过。
- 阶段通过：本表对应行的每个条件及其前置依赖均有证据。

构建/导出脚本只实施部分检查，不能以返回码或导出包代替本表。新增可观察算法须同时满足软件先行A–G；G1/G2未过不正式集成新算法。G6基础OSD可以按PHASES解耦准备，但整项G6仍须G4/G5。

## 判定规则

状态只用：未执行、进行中、阻塞、失败、通过。已有部分证据可注明，但不能替代整项通过。失败原因已定位只表示完成排错记录，不是阶段退出。每项测试必须绑定源文件版本或清单哈希、工具版本、配置、输入、预期、实际和原始证据。

下列次数与时长为本项目本轮规划值，不是官方要求或实测性能。开测前冻结；调整须在实验记录中写理由并保留原值，不能看完结果后放宽。定位误差、漏检/误检、计数稳定性、鲁棒性和资源余量等依赖模型与工位的指标暂不猜值：未填具体数值、单位、测量方法和依据时，该项为阻塞，不能通过。

## 执行记录模板

复制以下字段到对应实验记录；空字段或占位符不计通过证据。

- 验收 ID / 状态 / 日期 / 执行者：
- 源码 commit；有未提交修改时附源文件清单及 SHA-256：
- 工程变体（原版/clockfix/算法版本）、TD/IP 版本、器件、顶层：
- Bitstream 路径与 SHA-256；对应构建日志、route 报告：
- 板卡/模组修订、供电、线缆、显示器、工位与测量仪器：
- 输入样本与校验值、参数、预期值、容差/次数/时长（开测前冻结）：
- 可复现命令或 GUI 步骤、开始/结束时间：
- 实际结果、成功/失败次数、误差、原始日志/波形/视频路径与时间点：
- 证据类型（official/project/measured/reference/inferred/unknown）：
- 首个失败及恢复步骤；尚未关闭的缺口：
- 逐项判定及下一步：

告警台账逐条记录：版本、告警编号、网络/端点、严重度、原因、处理、证明材料、状态（已修复/已证明无害/阻塞）。时序通过或短时间画面正常不能单独证明时钟/CDC 告警无害。
