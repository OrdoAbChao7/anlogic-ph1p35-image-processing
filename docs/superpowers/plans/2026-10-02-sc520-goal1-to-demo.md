# SC520CS PH1P35 视频链路与竞赛 Demo 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 TD 6.2.1 和 PH1P35/HX1P35A 环境下，先复现 SC520CS 到 HDMI 的稳定视频基线，再逐级加入灰度、二值化、Sobel、目标统计、工业测量/缺陷判定和 OSD。

**Architecture:** 保留 SC520CS Lab1 已有的 MIPI、DDR、PLL、HDMI 和板级约束边界，先以原始视频链路作为唯一基线。算法作为明确像素流接口之间的独立层逐级接入；每一阶段都保留可回退的稳定版本，并以构建报告、仿真结果和上板记录作为阶段门证据。

**Tech Stack:** TangDynasty TD 6.2.1 build 168116、PH1P35MDG324、HX1P35A、SC520CS、Verilog/SystemVerilog、TD 工程/IP/约束、模块仿真和板级 HDMI 验证。

**Spec:** `AGENTS.md`；`docs/research/goal-reading/goal-1.md` 至 `goal-8.md`；`docs/research/known-gaps.md`。

- 摄像头目标固定为 `SC520CS`；比赛资料中的 `SC500CS` 例程只能作为参考，不能直接当作 SC520CS 已兼容证据。

- Goal 1 视频硬件闭环未通过前，不接入应用算法和 OSD。
- 不修改厂商生成 IP；IP 变化必须可追踪并能回退。
- 所有关键结论标注 `official`、`project`、`measured`、`reference`、`inferred` 或 `unknown`，并记录证据路径。
- 仿真、综合、实现、上板和长稳结果分层记录；没有硬件证据不得使用“稳定”“无丢帧”等表述。
- 保留用户已有修改；构建生成物与手写源文件分离，临时文件在任务结束后清理。

## Review Focus

- SC520CS 传感器配置与当前模组修订不匹配：以初始化代码、资料和上板启动结果核对，不能只按目录名判断。
- SC520CS RAW/Bayer/输出位宽不明确：在进入灰度前锁定格式并保留原图对照。
- MIPI/DDR/HDMI 时钟域和同步语义不明确：接口表必须记录时钟、valid、DE、HSYNC、VSYNC、CDC 和延迟。
- 构建成功但关键告警或时序未收敛：构建报告必须分类记录错误、告警、WNS/TNS 和关键路径。
- 算法接入造成画面错位或模式切换破坏整帧一致性：每级算法都要做控制信号对齐、边界和模式切换验证。
