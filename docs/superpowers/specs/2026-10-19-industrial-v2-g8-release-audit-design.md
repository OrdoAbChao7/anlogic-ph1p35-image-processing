# Industrial Vision V2 G8 发布审计设计

## 目的

为最终整机发布建立一个可重复的只读审计入口。审计只能把有明确证据的条件记为 `PASS`；模块级软件/RTL 通过、用户默认视觉批准或 V1 历史位流都不能替代同一 V2 Bitstream、TD、硬件和长稳证据。

## 输入

- `docs/goals/industrial-v2/STATUS.json`：阶段状态、V1 冻结基线和用户视觉批准策略。
- V1 冻结位流及其 SHA-256：只做基线保护复核，不作为 V2 发布物。
- V2 发布目录和 TD 证据目录：当前不存在时必须报告缺失。
- Git `HEAD`：绑定审计快照。

## 十二项 G8 退出门

1. 七项功能的软件、RTL 和 TD 验证。
2. 七项功能存在于同一 V2 Bitstream。
3. V1 核心功能回归不退化。
4. 完整 V2 TD 综合、布局布线、Hold Fix、STA 和 Bitgen。
5. V2 资源及时序满足冻结预算。
6. 时钟、PHY、CDC、未驱动信号和约束例外审计完成。
7. 完整上板功能矩阵。
8. 性能和检测实验可追溯。
9. 冷启动、热复位、重复下载和长稳通过。
10. 构建和发布包可从干净环境复现。
11. 外部执行机构实际控制验收。
12. 视觉审批已获得；本项目按用户指令将 Stage C 视觉审批记录为已授权，但不扩大到硬件验收。

## 判定规则

`release_status=RELEASED` 当且仅当十二项均为显式 `PASS`。`BLOCKED`、`NOT_RUN`、`MISSING` 或未识别状态都阻止发布。脚本支持 `--strict`，阻塞时返回非零，适合作为冻结前检查入口。

## 当前边界

当前只实现审计入口和证据绑定，没有修改 V2 正式顶层、没有运行 TD、没有生成 V2 Bitstream，也没有制造板卡或执行机构证据。审计输出中的 V1 基线 `PASS` 只表示其 SHA-256 与冻结记录一致。
