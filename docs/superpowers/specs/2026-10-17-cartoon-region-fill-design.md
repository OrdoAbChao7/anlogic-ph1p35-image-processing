# 卡通化区域填充设计规格

## 1. 状态与目的

- 日期：2026-10-17
- 设计状态：用户已批准进入设计规格阶段；新的视觉参数仍需经过 Stage B/C 预览确认后，才能替换正式冻结版本。
- 当前正式基线：`s3_luma`，即平滑、亮度量化和 Sobel 轮廓；它保留为可回退版本。
- 本规格解决的缺口：比赛项目要求中的“颜色量化 + 区域填充 + Sobel 轮廓融合”目前尚未在 `s3_luma` 中实现。

本设计只扩展卡通化支路，不改变固定红色零件检测、OSD、按键和 HDMI 的接口契约。没有硬件板卡时，本规格及其后续仿真不能证明 Stage G 上板通过。

## 2. 目标与非目标

### 2.1 目标

在现有 RGB888、一像素/拍、无背压的视频接口上，形成可综合、可逐像素比对的卡通化候选：

1. 对每个通道做固定 8 级颜色量化，保留颜色差异。
2. 用有限窗口完成确定性的局部区域填充，填补被量化噪声打穿的单像素孔洞。
3. 将量化图的 Sobel 轮廓与填充后的颜色合成，轮廓输出黑色、区域输出量化颜色。
4. 在帧边界切换 Original / Sobel / Cartoon，所有同步信号与像素保持同周期对齐。
5. 用软件参考模型、硬件等价模型、RTL 仿真和 TD 构建逐级验证。

### 2.2 非目标

- 不实现任意尺寸的全帧连通域标记、洪泛填充或迭代收敛。
- 不把全帧数组、不可综合的 Python/OpenCV 结构或外部运行时参数带入 RTL。
- 不修改当前已批准的 `v1.0-approved` 工业检测参数。
- 不在没有新的视觉确认前，把候选算法写入正式发布位流或把旧的 `VISUAL_APPROVED` 复用于新视觉效果。

## 3. 精确定义

### 3.1 输入和量化

输入是 `RGB888`，有效条件为 `i_de=1`。对每个通道 `v` 定义 8 级量化代表值：

```text
level(v) = v[7:5]
Q(v)     = (level << 5) | (level << 2) | (level >> 1)
```

量化对 `R/G/B` 独立执行，输出仍为 `RGB888`。同一公式必须出现在 Python 参考模型和 Verilog RTL 中；不使用除法、浮点或隐式有符号运算。

### 3.2 窗口与边界

每个输出像素使用现有行缓存可提供的 causal `3×3` 量化窗口：当前接受的像素是窗口右下端，窗口逻辑中心为 `e`，对应的区域填充结果随固定流水线延迟输出。视频边界使用 `BORDER_REPLICATE`；对于这个右下锚点，实际需要复制的输入边界是上边和左边，右边和下边没有被未来采样访问，因此不需要人为插入尾部像素。空白区不推进图像坐标，也不更新区域状态。

窗口和四连通邻居记为：

```text
    a  b  c
    d  e  f
    g  h  i

其中 `C=e`、`N=b`、`S=h`、`W=d`、`E=f`。
```

### 3.3 局部区域填充

定义量化后的中心颜色 `C` 和四个邻居颜色 `N/S/W/E`。填充结果 `F` 为：

```text
if N == S && S == W && W == E:
    F = N
else:
    F = C
```

这里的相等是三个 8 级通道量化值的逐通道相等。该规则是一个确定性的四连通局部区域填充：

- 单像素孔洞会被四个同色邻居填满；
- 跨越真实颜色边界时不会凭空跨区域填色；
- 同色平坦区保持不变；
- 规则只需当前 `3×3` 窗口，不需要标签 RAM 或全帧回写。

这一定义明确限定了“区域填充”的范围。它不是任意连通域洪泛填充；若比赛评审要求后者，应另立版本和资源预算，不能把本算法描述成全局连通域填充。

### 3.4 Sobel 与融合

Sobel 输入为同一 `3×3` 量化窗口的亮度：

```text
Y = (R + 2*G + B) >> 2
```

使用标准 `3×3` Sobel 核，计算 `|Gx| + |Gy|`，固定阈值为 `240`；中间结果使用显式有符号位宽，绝对值和比较不依赖 Verilog 默认扩展。若结果大于等于阈值，则 `edge=1`。

卡通模式输出：

```text
edge == 1  -> 24'h000000
edge == 0  -> F
```

OSD/Logo 覆盖仍位于算法输出之后，覆盖像素不参与卡通化和检测统计。

## 4. RTL 接口与时序

候选模块沿用现有 `video_cartoon` 接口：

| 信号 | 定义 |
|---|---|
| `i_vs/i_hs/i_de` | 输入视频同步；只有 `i_de` 推进图像坐标 |
| `i_rgb[23:0]` | RGB888，`[23:16]=R`、`[15:8]=G`、`[7:0]=B` |
| `i_edge_req/i_toon_req` | 模式请求；同步后只在新帧首个有效像素锁存 |
| `i_overlay/i_overlay_rgb` | OSD 覆盖请求和颜色 |
| `o_vs/o_hs/o_de` | 与输出像素同延迟的同步信号 |
| `o_rgb[23:0]` | Original / Sobel / Cartoon 输出 |
| `o_mode[1:0]` | 与输出像素对应的当前模式 |

实现目标是维持现有候选的 6 个有效时钟延迟，并让 `VS/HS/DE/mode/overlay` 全部经过相同数量的寄存器级。正式延迟必须由 RTL 波形和契约测试冻结，不能仅由本规格推断。

复位清空窗口移位寄存器、坐标、模式和旁带流水线；帧尾之后必须有明确的流水线排空行为，不能把上一帧的窗口数据带入下一帧。非法模式回退到 Original。

## 5. 软件优先阶段

### Stage B：软件参考模型

新增独立模型 `work/models/cartoon_region_fill_reference.py`，不修改 `cartoon_luma_reference.py`。模型输出：

- 量化颜色图；
- 区域填充颜色图；
- Sobel edge mask；
- 融合后的 Cartoon RGB；
- 边界和填充统计。

Algorithm Lab 增加候选 `s4_region_fill`，候选参数至少包括量化级数（固定 8 级）和 Sobel 阈值（默认 240）。候选参数保存为新文件，不覆盖 `approved_v1.0-approved.json`。

### Stage C：视觉确认

使用现有城市图和工业样本生成并列预览，至少观察：平坦色块、单像素孔洞、细线、真实边界、四边角和高噪声区域。只有用户对新的候选版本明确给出 `VISUAL_APPROVED`，才能进入 Stage D；在此之前禁止把候选加入正式 TD 工程。

## 6. 硬件等价模型与 RTL 计划

Stage C 通过后：

1. 在 `work/models/` 增加硬件等价模型，固定 8 级量化、3×3 边界复制、四连通填充、Sobel 位宽、阈值和输出优先级。
2. 新增独立 RTL 文件或等价候选模块，优先复用现有行缓存边界结构；不直接覆盖已通过回归的 `video_cartoon_luma.v`。
3. 编写 Icarus Testbench，对模型输出和 `RGB/VS/HS/DE/mode/overlay` 做逐周期比对。
4. 先跑小窗口边界向量，再跑连续帧和 `1280×720` 全帧；通过后才允许接入 TD 工程。
5. 运行 TD 综合、布局布线和报告解析，单独记录 Slice、RAM、DSP、WNS/TNS、告警和位流哈希。若资源或时序不达标，保留失败证据并回退到 `s3_luma`，不能把候选标成正式版本。

## 7. 验证矩阵

| 类别 | 必测场景 | 通过条件 |
|---|---|---|
| 量化 | 黑、白、纯红/绿/蓝、量化边界前后 | Python 与 RTL 逐像素一致 |
| 填充 | 中心单像素孔洞、四邻居不一致、平坦区 | 只在四邻居同色时填充 |
| 边界 | 左右上下边、四角、单行/单列最小图 | 与 `BORDER_REPLICATE` 一致，无越界旧数据 |
| Sobel | 常量、水平/垂直阶跃、斜线、孤立点 | 梯度位宽、绝对值、阈值和黑色轮廓一致 |
| 视频 | 连续两帧不同图、帧尾排空、空白区停顿 | 无帧间污染，旁带与 RGB 同周期 |
| 模式 | Original/Sobel/Cartoon 请求在帧中途变化 | 只在帧首生效，整帧模式一致 |
| OSD | Logo、文字、检测框覆盖 | 覆盖颜色不被卡通化，位置和延迟一致 |
| 构建 | TD 综合、布局布线、重复构建 | 时序/资源门槛及告警分类有原始报告 |

## 8. 风险、回退和发布边界

- 3×3 局部填充的语义弱于全局连通域填充；规格已明确这一边界，避免答辩时夸大功能。
- 新逻辑会增加颜色比较器和 Sobel 输入选择，当前 fixed-red v1 已接近 80% Slice 预算，资源和时序必须重新实测。
- 新候选的视觉批准、参数哈希、模型哈希、RTL commit、TD 报告和位流哈希必须成套绑定。
- 在 Stage C/F/G 全部通过前，正式发布仍使用 `s3_luma`；任何候选失败都不能覆盖旧位流、旧报告或用户已有的 `fallback/tb_color.vvp`。
