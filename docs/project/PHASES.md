# PHASES — 阶段依赖与执行映射

本页只定义依赖和范围，不复制当前状态。状态见 [STATUS](STATUS.md)，通过条件以 [验收矩阵](../verification/acceptance-matrix.md) 为准，执行命令见 [工具链](../development/toolchain.md)。2026-10-20整理不降低任何验收标准。

## 1. 三套编号不能混用

| 编号 | 含义 | 能证明什么 |
|---|---|---|
| G1–G8 | 主系统阶段 | 只有对应全部验收条件通过才退出 |
| F1–F5 | 独立传统工业视觉路线 | 自身模块/应用/交付范围，不替代G5神经网络 |
| P0–P8 / B0–B6 | 整合实施工作包/候选里程碑 | 工作顺序和恢复点，不是另一套更宽松的验收标准 |
| Stage A–G | 每个算法的软件到硬件生命周期 | C视觉批准、D等价、E仿真、F构建、G硬件各自独立 |

例如“G3算法的Stage F通过”只证明该算法候选构建，不代表主系统G3通过。BUILD_PASS、SIM_PASS不是阶段编号。

## 2. 主系统依赖

~~~text
G1 → G2 → G3 → G4
          └─ G3满足后可推进G5（同时依赖G2）
G4 → G6基础OSD
G4 + G5 → G6完整验收 → G7 → G8（必须G1–G7全部通过）
~~~

G5采用既有阶段表及验收矩阵的G2/G3依赖；旧总图额外画出的G4→G5箭头是历史示意冲突，不新增或删除矩阵中的门。G6基础OSD可独立于G5准备/实现；完整检测与外设验收仍须G4/G5。G2在G1前允许只读审计，正式冻结须G1通过。

| 阶段 | 前置 | 本阶段必须交付 | 验收入口 |
|---|---|---|---|
| G1 视频闭环 | 工程/资料可定位 | 原图可重建位流、时钟/告警审计、下载/冷启动/复位/重下载/帧率证据 | G1-B与G1-H全部通过 |
| G2 接口/ISP | G1；只读审计可提前 | RAW/Bayer/CSI/ISP/DDR/HDMI、位宽、4ppc/1ppc、CDC、背压、复位、缓存和延迟契约 | G2；正式契约计划路径docs/architecture/sc520-interface-contract.md，不把草案称冻结 |
| G3 三模式/卡通 | G1/G2；算法A→G | DDR前96bit/4ppc原图/边缘前置/卡通，颜色量化、区域填充、模式与控制对齐 | G3，必须包含区域填充和上板切换 |
| G4 Sobel | G3；算法A→G | 流式Line Buffer、3×3窗口、明确梯度/阈值/边界/空间偏移、资源与时序 | G4，像素及控制比对、上板10min |
| G5 裁剪检测网络 | G2/G3；模型效果及硬件预算GO | 可追溯INT8模型、算子/缓存/调度/解码/NMS、类别/BBox/总数 | G5及冻结工位指标，不能仅PE通过 |
| G6 OSD/外设 | 基础OSD依赖G4；完整依赖G4/G5 | Logo、模式、帧计数、类别/框/总数，按键、有效事件LED/WM8978 | G6；复位/空场/重复/异常均验证 |
| G7 优化创新 | G6稳定版本 | 2–3项同输入单变量对照、量化收益和硬件演示 | G7，不能用PC效果充当FPGA创新 |
| G8 冻结发布 | G1–G7全部通过 | 从冻结包重建、另一队员操作、长稳/演示、完整材料 | G8，冷启动/复位/下载各10次、4h、演示3次 |

具体次数、判定与证据模板不在阅读清单/Skill中另定。既有候选越过阶段的历史事实不授予继续跨门的权限。

## 3. 传统路线与整合计划

F1颜色分割/统计/BBox修复 → F2形态学 → F3几何/标定 → F4缺陷判定；F5维护可重建候选包。软件准备、隔离模块验证及恢复包整理独立于主线神经网络进度；新功能正式接入视频仍须G1/G2和算法效果门。F5候选导出不表示F1–F4应用与硬件验收全部通过。

实施顺序参见 [Agent工作流](../development/agent-workflow.md) 和 [整合方案](../development/integration-plan.md)：P0基线、P1预览、P2帧关联、P3最小演示、P4三模式、P5外设、P6多目标、P7裁剪网络、P8发布。基础演示按范围单独记录，不改主线退出条件。

## 4. 每次跨门的检查

1. 前置阶段的PASS指向具体版本和证据；不能只写“之前做过”。
2. 本轮输入、公式、参数和效果批准相符；有变化先确定哪些证据失效。
3. 对照验收矩阵逐项填写实际结果；缺数值指标、原始证据或硬件观察则保留阻塞。
4. 写入实验/构建/硬件记录，再更新STATUS；失败保留首败与恢复步骤。
5. 再开始下一个依赖阶段；解耦的只读或软件工作可继续。
