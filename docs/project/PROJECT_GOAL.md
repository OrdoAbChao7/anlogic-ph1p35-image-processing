# PROJECT GOAL — 稳定目标与交付边界

本页只定义“要交付什么”，不记录当前完成度、安装路径或资源余量。2026-10-20按用户文档整理指令重写；保留三模式、裁剪检测网络、LED、WM8978与性能目标。改变功能、主备取舍、目标指标或验收范围须用户明确批准，并记录到docs/decisions；普通修复与归档不得改变目标。

## 1. 项目使命

面向2026全国大学生嵌入式芯片与系统设计竞赛安路赛道题目二，在HX1P35A / PH1P35MDG324上完成可复现、可量化、可现场演示、可答辩的无软核实时图像处理与简易工业视觉分拣作品。

目标摄像头为SC520CS，MIPI输入、HDMI输出。SC500CS工程只作参考，不作为当前摄像头配置依据。实际RAW位宽、Bayer、Lane速率、寄存器、管脚和时钟须由工程及板级证据确认。

| 目标指标 | 性质与验证要求 |
|---|---|
| 输入1280×720 RAW10 | 项目目标；核对传感器配置与实际输出 |
| HDMI 720p@30fps | 项目目标；分别报告摄像头唯一新帧率与显示刷新率 |
| 端到端延迟小于2ms | 项目目标；包含采集/处理/缓存/显示，不能用算法拍数替代 |
| 新增应用RTL纯Verilog、无软核CPU | 实现约束；保留既有厂商SV/加密IP，不强改厂商源 |
| Setup/Hold WNS≥0、TNS=0 | 必须与约束覆盖、CDC和告警审计一起判断 |
| Slice占用严格小于80% | 项目余量目标；RAM/DSP及各功能预算也须冻结并验证 |

以上不是当前已达成指标。官方基础要求与项目扩展分别追溯至 [比赛要求](../research/competition/topic2-requirements.md) 和对应正式PDF，不能把项目目标表述为全部官方必选。

## 2. 必须交付的功能

### 视频与三模式

SC520CS → MIPI D-PHY/CSI-2 → ISP（拜耳解码、白平衡）→ 图像处理/DDR2 → HDMI。

该表达仅描述功能链；正式插入点遵循ADR-002：图像算法在DDR前ISP域的RGB888、96bit四像素流上适配，HDMI侧单像素域叠加OSD。不能据概念图挪动厂商接口。

- 原图：ISP输出直通。
- Sobel：可综合Line Buffer、3×3窗口、明确位宽和边界策略的实时流水线。
- 卡通化：颜色量化、区域填充与Sobel轮廓融合；仅量化/描边不算完整卡通化目标。
- 按键切换在约定帧边界生效，各模式像素格式、尺寸和同步一致；实际按键映射以原理图及实物为准，不能挪用已有增益键。

### 检测与统计

主线目标保留INT8量化裁剪YOLO方向；可研究Micro-CNN/裁剪结构，每阶段重评效果、存储、吞吐和资源可行性。历史GO只是研究方向，不是硬件可行性证明。

交付包含模型/权重/量化来源、ROI与缩放、卷积、池化、激活/重定标、特征缓存、候选框解码、NMS、定位、类别与真实目标总数。纯Verilog控制；检测结果整组发布，绑定来源帧并在显示帧边界稳定更新。

PC大模型只作视觉参考；模型软件效果未通过不得进入整网硬件化。检测更新率与视频帧率分别测量，不能默默降低既定指标。

### OSD与外设

OSD至少包含安路Logo、当前模式、帧计数、检测框、类别、目标总数和检测状态。显示CNT、捕获帧ID与结果帧ID含义不同；文字与框必须对应同一显示快照。

板载按键、LED与WM8978语音属于完整项目目标。仅有效检测事件触发，明确复位、空场、重复检测、重复显示、错误与播放中断行为。基础OSD可独立推进，不以检测网络未完成为理由重复开发已有Logo或阻塞解耦准备。

## 3. 传统工业视觉备选与最小演示

独立保留传统路线：颜色/灰度分割 → 形态学 → 包围盒/面积/质心 → 标定与PASS/NG → OSD/LED。阶段F1–F5见 [备用状态](../fallback-status.md)。

当前最小演示的设计范围是原图/现有Sobel、Logo/CNT、颜色全局框、模式/检测状态/坐标/面积/帧龄。它可以按自身范围验收，但不能替代三模式、神经网络、多目标、语音或完整G1–G8交付。单全局框不能代表真实物体数量或识别类别。

YOLO研究目录归档不等于取消目标；恢复研究须先通过软件效果门，不自动加入当前视频工程。

## 4. 完整成功定义

必须同时具备：可重复视频闭环；逐阶段实际接入的ISP/三模式/检测；完整OSD；有效事件外设联动；资源/时序/帧率/延迟/精度依据；分层仿真、实现、上板和异常测试；干净环境可重建交付；2–3个有基线、量化收益和硬件演示的创新点。

最终包包含源码/约束/IP配置、模型/权重/参数、位流及哈希、架构与接口、测试与原始报告、硬件和长稳证据、操作手册、演示视频、PPT、FAQ、分工和比赛要求映射。完整清单见 [工程细则](../development/engineering-rules.md)。阶段数值与发布测试统一见 [验收矩阵](../verification/acceptance-matrix.md)。

## 5. 非目标与变更控制

不使用软核CPU，不直接套用其他平台PHY/CSI/DDR/PLL/HDMI原语或约束；不凭教程猜寄存器和管脚；不以上位机效果代替PH1P35实现；不以新增功能破坏已验收恢复版本。

已有架构取舍见 [ADR-001至003](../decisions/ADR-001-003-architecture-baseline.md)；其中过期器件资源数字仅保留历史，当前预算必须用对应版本最终报告。状态只在 [STATUS](STATUS.md) 更新；阶段依赖只在 [PHASES](PHASES.md) 维护。
