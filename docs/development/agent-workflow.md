# Agent 工作流

本页回答：现在做什么、在哪里做、满足什么条件再继续。稳定目标见 [PROJECT_GOAL](../project/PROJECT_GOAL.md)，最新证据见 [STATUS](../project/STATUS.md)，精确命令见 [工具链](toolchain.md)。

## 1. 接手一个任务

1. 读取上述目标与状态，区分用户要的是查询、修复、功能开发还是阶段验收。
2. 检查 git status、相关 diff、当前分支和 .al 输入。已有 dirty 工作区不是清理授权，提交号不能单独标识未提交候选。
3. 写出“对象 / 工作区 / 前置门 / 本轮输出 / 退出条件”。未指定 Goal 时按下表定位。
4. 读取对应规范和缺口，核对现有结果适用的输入哈希。通过记录与当前输入不同则不得沿用。
5. 执行最小相关验证；失败保留首个根因证据，只修改足以验证假设的变量。
6. 归档证据，更新 STATUS 和相关缺口，交付明确下一入口；不要重复执行已经通过且未受影响的检查。

## 2. 按任务选择路线

| 用户任务 | 工作对象与入口 | 本轮退出条件 |
|---|---|---|
| 查进度、解释架构 | STATUS → 对应报告/.al/源码；只读 | 当前事实与计划分开，能定位证据，不启动 TD |
| 整理文档 | 修改对应职责文档，查脚本参数 | 链接、命令、标准、历史兼容性检查通过；不提升功能状态 |
| 原图无画面、启动异常 | G1 基线、接线、配置与最小故障证据 | 根因与恢复可复现；完整 G1 仍按矩阵判定 |
| 接口、FIFO、CDC、帧关联 | G2 接口账本、实际 .al、整合计划 P0/P2 | 每段依赖有来源、波形和异常语义；未确认项仍阻塞对应集成 |
| 卡通、Sobel、颜色/多目标、OSD效果 | Algorithm Lab → A/B/C；随后 D/E/F/G | 具体版本的效果批准、定点等价、RTL、整机与上板分别通过 |
| 已有 RTL 缺陷 | 首个失败向量 → 对应模型/测试 → 最小修复 | 原失败和受影响回归通过；不把等价修复当新算法批准 |
| 独立颜色模块测试/预算 | fpga_loop，当前实际支持 color_detect_96 | summary 内测试与目标哈希正确；模块综合不等于整机可容纳 |
| 整机集成与导出 | work/integration 的 test.ps1 → build.ps1 → export.ps1 | 同一输入清单通过测试、时序和导出；仍标待上板 |
| G 阶段退出/发布 | PHASES + 验收矩阵 + 当前版本完整证据 | 所有条件满足才通过，缺项不能用部分 PASS 抵消 |

工具未安装、器件未连接与算法前置门未通过是不同阻塞。硬件阻塞时仍可进行文档审计、A/B 软件预览和已经具备前置条件的隔离验证；不得自动跨过 C 或系统集成门。

## 3. 推荐执行顺序与成果边界

P 编号是 [整合方案](integration-plan.md) 的工作包，不替代 G 阶段验收；A–G 是每个算法自身的生命周期。

| 顺序 | 本轮应交付什么 | 继续条件 |
|---|---|---|
| P0 基线与接口取证 | 恢复点清单、G1记录、G2接口与告警账本 | G1/G2满足对应矩阵；保留未关闭告警 |
| P1 软件预览，可与P0独立推进 | 原图/边缘、颜色框、MODE/DET/坐标/面积/帧龄预览 | 用户确认具体效果，冻结参数与样本，完成定点模型 |
| P2 帧关联 | 捕获ID、结果ID、槽号/代次、完整帧提交、整组CDC | 连续帧、重复显示、乱相位、复位、丢包/短帧回归通过 |
| P3 最小演示 B1 | 已有Logo/CNT + 模式/状态/坐标/面积文字，框与文字同快照 | 模型/RTL、整机构建及同屏上板通过；边缘10min、首版30min冒烟 |
| P4 三模式 B2 | Sobel等价优化、四像素卡通、区域填充、模式同步 | 新效果软件验收；完整G3/G4通过，不能仅以量化描边交付区域填充 |
| P5 外设 B3 | 有效检测事件、去重、LED、WM8978配置与播报 | 引脚和电气有据；空场/复位/重复帧不误动作；完整G6仍依赖G5 |
| P6 多目标 B4 | 分割/连通域、独立框列表、真实数量 | 冻结容量/最坏噪声/溢出与计数指标；软件到硬件均通过 |
| P7 神经网络 B5 | 合格模型、INT8等价、存储/周期预算、算子、整网、NMS | 软件效果先过门；G5及视频/外设并发回归通过 |
| P8 完整发布 B6 | 量化创新对照、冻结包、重建、长稳、演示与答辩 | G1–G8完整通过；B1不得冒充B6 |

当前默认下一步由 STATUS 指定，不自动按表把所有功能一次性实现。P5/P6 与 P7 的软件准备可以解耦；正式阶段退出继续遵守 PHASES。

## 4. 固定架构边界

- 整合采用 fallback 修复候选的独立副本 work/integration；不在恢复包内继续开发，也不覆盖另一工作区。
- 保留厂商 MIPI/ISP、DDR2、HDMI、PLL 与约束边界。DDR 前 RGB888 96bit/4ppc 做算法和统计，HDMI 24bit/1ppc 做文字 OSD。
- 检测从未画框的 ISP 输出分叉，不能对边缘图或已叠加文字再检测。
- 首版保留既有次帧绘框，传送与实际绘框一致的结果快照；标明来源帧与帧龄。不能在 HDMI VS 时直接拿“最新 det_*”。
- 模式写入对应帧元数据；显示重复旧帧时不得重新触发检测事件。完整帧提交、DDR槽覆盖、FIFO满/空、错误失效都需要验证。
- 单全局颜色框只证明颜色范围命中，不证明物体类别或多目标数量。面积为命中像素数，不能直接标为毫米面积。
- 卡通单像素候选不能直接接四像素母工程；跨lane窗口、行边界和总延迟须重新验证。
- 预算使用目标版本最终 route.qor，不能沿用旧Lab1的空闲DSP或过期ADR容量。端到端延迟包含采集、缓存和显示，不能仅报算法拍数。

## 5. 什么时候需要用户输入

- C阶段：提供可运行预览、样本与参数后，请用户确认效果；本轮任务授权不等于视觉批准。
- 工位验收：先整理已有样本和建议测法，再确认类别/尺度/光照范围与数值指标；未冻结指标不判通过。
- 目标/阶段/标准变更：提交具体影响与替代方案；保留现有要求直至明确授权。
- 一般源码修复、证据补全、文档更正和已授权任务无需反复询问。无法上板时交付可审查结果，并说明缺的是设备、资料还是决定。

## 6. 收尾清单

- 输出准确区分 project 与 measured，本轮执行与历史证据。
- 测试/构建报告绑定同一输入清单；bit、route、源码不跨版本拼接。
- STATUS只写简明当前结论与下一步，详细记录放实验/构建/证据目录。
- 清理可重建临时物前保留复现命令、必要原始日志和失败证据；历史原始目录已清理的记录只能称摘要。
- 不自动提交、推送或部署；按用户任务范围执行。交付指出未通过门，不重复已确认信息。
