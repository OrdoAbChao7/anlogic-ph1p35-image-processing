# 发给进行中 Industrial V2 Goal 的纠偏提示词

请将本消息作为对当前 Goal 的执行纠偏，继续原 Goal，不新建 Goal，不删除七项功能，不修改被冻结的 V1 或现有正式候选包。先完成正在运行的构建的结果收集与归档，再改变执行方向；不要启动重复构建或丢弃当前失败证据。

## 本轮目标

将重心从“G8发布收尾/反复清告警”转回“完整七功能当前源码的资源、时序、帧关联和可复现性收敛”。只有同一版本满足全部条件才能晋升，禁止把旧位流的TD通过与新源码的测试通过组合为一个通过版本。

先核对当前工作区和最新证据，不假定下面的快照仍是最新结果：
- 旧正式候选约80.72% Slice、WNS +104/+20ps；它是恢复参照，不证明后续AWB/遥测修复已进入位流。
- fix8记录为22420/21216 Slice（105.68%）、gate Setup WNS -7216ps、DSP 40/40，PHY-9053终止，没有新位流。
- 组合时钟探针的“PHY告警全部消失”已经更正：原始内层flow_exec.log仍有PHY-5016/5088。
- HDMI视频事件/帧ID曾为tie-off，DDR四帧槽缺完整帧标签与写完成关联，E2E仍不可用。
这些是待复核的历史事实，不是可以直接沿用的新测试结论。

## 必须改变的执行方式

1. 停止没有明确假设的seed遍历、重复全量测试和I2C计数器微调。未有新证据时，不把改seed或模型切换当技术进展。
2. 不修改七项功能语义、精度/吞吐、异常帧行为或资源门限以换PASS。使用V2自身已授权预算；核对<=85%、>90%暂停合并、>=95%不正常发布的原文与适用范围，不套用另一个项目的80%门限。
3. Stage C继续遵守我此前“实验室视觉审批默认授权”的指令，不再次索取相同批准；保留输入、参数与等价误差证据。该授权不代替硬件、测量、标定和执行器验收。
4. 从现在起，每个实验只回答一个问题：假设、唯一变更、固定输入、预期判据、实际结果、下一决定。没有明确判据的实验不启动。
5. 测试先跑受影响模块，再跑必要上层。新失败必须保留首败证据，不靠新增形式测试的数量体现进度。

## 执行顺序

### A. 先冻结真实基线和证据

区分V1恢复包、旧V2候选、当前源码、最新失败构建。逐项绑定完整输入清单、参数/约束/IP/ROM初始化文件、工具/flow/config、生成脚本、原始日志、报告和位流（若有）。记录Git已有修改，不覆盖其他工作。

把未闭合项分成：源码功能缺口、资源/时序失败、工具可复现性、时钟/CDC、待硬件验收。严格审计必须标明它审的是哪个版本。失败构建也保存provenance，不能等bitgen成功才生成清单。

### B. 首先完成面积与关键路径归因

读取当前完整版本的层级area、RAM/DSP推断和最差路径，列出资源大户及直接证据，优先检查motion_diff_160历史存储和AWB增益计算，不预设它们是全部根因。

不要把gate阶段约47%的摘要当成最终利用率。以实际放置/route为准：若仍为22420 Slice，达到器件容量至少要减少1204，达到<=85%预算至少要减少4387；仅减少1204不算达标。

按证据选择一个结构性优化，优先考虑：
- 历史图像存储的ERAM实现：先冻结读写延迟、端口、复位、首帧、短帧/缺SOF、无效帧是否更新历史的语义，禁止为了推断RAM取消这些行为。
- AWB帧级算术分拍/共享：先计算真实可用周期，保持定点公式、舍入/饱和、吞吐、增益更新与SOF同沿规则；不得假定额外帧间空闲。

先做数学/RTL等价和定向回归，再做单模块映射试验，确认有明确收益后才启动一次完整集成构建。单模块收益不等于整机必然收益，最终仍看同版整机结果。

### C. 单独定位构建波动

不要把位流哈希不同直接认定为功能错误，也不要自行取消当前字节级复现门。按“输入与环境 → elaborate/RTL → gate → place → route → bitgen”定位最早差异；数据库字节不同不等于逻辑不等价。

固定源文件及顺序、参数、ROM/MIF/IP、全部设置、工具/flow、实际工作目录和环境、线程/seed设置，保存原始日志。优先利用已有成对产物，只补足必要复跑。若相同输入已在综合处分叉，就停止用place seed解释全部问题，建立最小复现，必要时准备厂商支持材料；对外发送材料前另行取得授权。

### D. 关闭帧关联和告警的真实缺口

帧标签跟随实际DDR写槽、写完成、读槽/代次及完整HDMI输出事件。不得用“当前输入帧ID”替代正在显示的缓存帧。覆盖重复显示、槽覆盖、缺失元数据、短帧、复位和CDC；接口完成前VIDEO/E2E保持N/A。

告警扫描必须读取TD内层原始日志，逐条记录时钟源、接收端、资源类型、约束与厂商依据。区分I2C、MCLK和DDR PHY根因；修正证据采集，不以换seed或屏蔽告警宣称关闭。

### E. 候选晋升与硬件交接

只有同一完整版本的功能、回归、实际资源、最终Setup/Hold/TNS、约束/CDC及适用告警审计满足要求，才评估晋升；复建仍须满足当前冻结的复现验收条件。不得挑最好seed掩盖跨预算波动。

无板卡时，完成可独立验证的软件/RTL/构建工作，并交付具体实验室清单；不要通过持续重复软件测试来尝试关闭硬件门。若所有剩余工作确实依赖设备/用户决定，按运行环境的Goal阻塞规则登记并交接，不把Goal标完成。

## 本轮交付与停止低收益尝试的条件

先交付“版本对应表 + 面积/关键路径归因表 + 首个单变量优化实验”，再依据证据推进，不一次性堆多个结构变更。

同一假设连续两次受控实验没有支持证据，停止该支线，记录否定结果并换有依据的假设；这是限制重复试错，不是降低完成标准。资料不足时先审计，不机械凑构建次数。

每次汇报包含：本轮解决了什么、尚未解决什么、源码/候选版本、关键数字与证据路径、下一实验的具体假设。保留首败、最终报告和复现输入之后才能清理临时数据库。不再重复整段历史或只报测试数量。

如证明保持全部七项功能与指标无法在PH1P35上收敛，交付带资源下界、关键路径、已验证备选与影响的可行性报告，请我决定目标/硬件取舍；不要擅自删功能或保证一定能完成。
