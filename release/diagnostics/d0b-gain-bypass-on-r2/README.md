# D0b — AWB 增益级旁路诊断位流

**用途：单变量判别实验，不是发布候选。**
**不得标记 `HARDWARE_PASS`。**

## 它是什么

`D0b = R2 − axis_gain_rgb96`

R2 的全部源码，去掉 `isp_top` 中插在 `awb` 与 `data_96bit_to_128bit` 之间的那一级
AWB 增益流水，用 5 条 `assign` 把 `awb` 直连到齿轮箱 —— 即 V1 的视频数据通路。
其余所有 V2 模块、连接、约束、IP 配置逐字节不变。

逐文件核对：相对 R2 只有 **`user_source/hdl_source/isp/isp_top.v` 一个文件改变**。
差异见 `evidence/ISP_GAIN_BYPASS.diff`。

## 为什么做这一版

对 V1 与 V2 做的逐文件差异审计（非 HDL 文件、DDR IP、`ddr2.adc`、`ddr2.sdc`、
PLL、`pin.adc`、`settings.cfg` 全部逐字节相同；视频链 12 个模块及其顶层接线
全部逐字节相同）得出一个结论：

> **整条视频数据通路上，V2 相对 V1 只多了一个元件** —— 就是这一级增益流水。

而静态推演说它应当透明（增益 256 = 单位增益；`S_ISP_O_tready` 恒 1 故不产生气泡；
下游齿轮箱相位只由 valid 游程决定，纯延迟不改变游程）。静态分析无法解释实测现象，
因此必须用一次单变量板测来判定。

## 启用的功能

与 R2 完全一致：MIPI 采集、ISP、DDR2、HDMI 720p、原图/Sobel/卡通三模式、
红色零件检测、OSD（安路 Logo + 12 行文字）、按键、LED、跟踪与运动遥测。

**关闭/抑制项（继承 AWB-Lite，非本实验引入）**：帧级 AWB 关闭（增益固定 1.0，
本版连增益级都旁路）；分拣执行器抑制（`I_arm=0`）。

## 怎么判读

在同一块开发板、同一个摄像头、同一台显示器、同一组线缆上，按
**V1 → R2 → D0b** 顺序各跑一次：

| D0b 现象 | 结论 |
|---|---|
| 画面正常稳定 | 故障与这一级增益流水相关。下一步不是直接删除它，而是查它在综合网表里的实际形态，再做一次对照构建排除布局因素 |
| 仍然闪烁/拼接/错位 | 该级被排除。RTL 结构已无差异，问题转向物理实现或帧缓存，转 D1（VTC 域彩条）/ D2（真实 DDR 写读已知测试图） |

无论哪种结果，请一并记录：

1. 画面是"整体错位"还是"局部拼接"，是否固定在某几行/某个区域
2. 闪烁是整帧闪还是局部闪，频率大约多少
3. OSD 的 `FRAME:` 计数是否稳定递增
4. 换模式（原图/Sobel/卡通）时故障是否变化

第 4 条特别有价值：如果三种模式**都一样坏**，故障在 `video_cartoon` 之前；
如果只有卡通模式坏，则锁定卡通路径。
