# D1 — OSD 字形修复诊断位流

**诊断位流，不是发布候选。不得标记 `HARDWARE_PASS`。**

## 它是什么

`D1 = D0b + OSD 字形列修复`

相对 D0b **只有 `industrial_osd_overlay.v` 一个文件改变**（差异见
`evidence/OSD_FONT_FIX.diff`，27 行）。

## 修的是什么

原实现：

```verilog
reg [4:0] current_row;                  // 字形 5 列，bit4 最左，bit0 最右
text_col = ((x - 180) & 7) >> 1;        // 只能取 0..3
text_on  = current_row[4 - text_col];   // 只索引 bit4..bit1
```

8 像素字格被压成 4 个字形列，**字形第 0 列整列永远画不出来**。
含右竖笔的字符（B、D、O、P、R、S、U、数字等）会缺笔画，且 4 列被拉宽填满
8 像素造成比例失真 —— 即板测观察到的"笔画缺失、错位"。

修复：字格改为 10 像素，`text_col = (off%10)>>1` 取 0..4，5 列各 2 像素均匀绘制。

**该缺陷 V1 同样存在**（相关表达式逐字相同），不是 V2 回归。Logo 走
`anlogic_logo_rom` 独立路径，故不受影响。

## 上板要看什么

1. **笔画完整** —— B、D、O、P、R、S、U 与数字的右竖笔应恢复
2. **比例正常** —— 字符不再被横向拉伸
3. **每行字符数变少** —— 字格 8→10 像素，一行 32→25 字符；最长行用到第 21 位，放得下
4. **画面仍稳定**，不闪
5. **`PROC/VIDEO/E2E` 仍显示 N/A —— 这是预期的**

## 边界

第 5 条是有意的：遥测 N/A 的根因是 `design_top_wrapper.v` 把 feature spine 的
整个 HDMI 视频契约硬接为零（第 1231–1237 行），需要单独一次改动（D2）。
本版**不包含**该修复，因此 N/A 不是回归。
